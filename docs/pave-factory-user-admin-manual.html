1. Scope

This manual covers how to operate and administer the PAVE Dark Factory Worker. The worker is not a general web application queue. It exists to work on CargoWise development tasks that are sourced from WiseTech Global PAVE through ediProd.

Primary rule: PAVE is the single source of truth for work discovery, priority, lifecycle state, assignment, audit trail, and final work item or incident reporting. The portal mirrors and explains what is happening; it does not replace PAVE.

The manual covers these operating surfaces:

  • Factory portal at http://127.0.0.1:5173/factory.
  • Scout worker process in app/backend/factory/worker.py.
  • Backend API under /api/factory.
  • SQL Server or SQLite factory storage providers.
  • WTG MCP dependencies: ediprod, wtgkb, and sbkb.
  • Archon workflow dispatch for normal delivery tasks and dedicated self-learning tasks.
  • Local service controller: scripts/factory-services.ps1.

3. Core Concepts

Scout Worker

A small low-token worker that polls PAVE, checks MCP readiness, checks the staff-code playing-task guard, ranks startable work, and creates a compact handoff. It should not perform expensive coding research while polling.

Intelligent Agent

The high-capability execution layer. It receives one PAVE task handoff, gathers task context with WTG knowledge, executes an Archon DAG, creates artifacts, runs a critic node, and reports back to PAVE.

Factory Portal

A central observability and control surface. It shows instances, active runs, stalled work, MCP readiness, tooling inventory, artifacts, critic output, eDoc uploads, and learning assessments.

PAVE Lifecycle

Claim, start, suspend, resume, complete, and assignment state belong in PAVE. The worker must not invent an independent queue or complete/suspend tasks only in the portal.

4. Quick Start

Start the local services

cd C:\git\dark-factory-experiment
.\scripts\factory-services.ps1 start
.\scripts\factory-services.ps1 status

Open the dashboard

http://127.0.0.1:5173/factory

Expected healthy local state

  • One current instance for C50 on Peter's Board.
  • Active runs should be zero while the scout is in dry-run mode.
  • Stalled MCPs should be zero when ediprod, wtgkb, and sbkb are ready.
  • Tooling should show runtime dependencies and skill/plugin catalogs separately.
  • Dry-run selected work should appear as dry run, not queued.
Do not enable live mode casually. PAVE allows only one playing task for a staff code. Starting a second task for the same staff code can suspend the first playing task.

5. Dashboard User Guide

Overview Tab

The Overview tab answers whether the worker pool is ready to act.

Area What to check Healthy signal
Instances Registered workers and their heartbeats. Only live workers appear. Stale historical worker IDs are filtered out.
Active queue Runs in queued, claimed, or running. Dry-run selections are not active queue items.
Stalled work Runs that need attention due to MCP, PAVE, Archon, or clarity failures. Empty during normal dry-run monitoring.
Required MCP readiness State of ediprod, wtgkb, and sbkb. All ready. Any stale/unauthenticated/unavailable state pauses affected processing.

Runs Tab

The Runs tab shows PAVE task selections and execution attempts. It should show human PAVE identifiers, including work item number, task code, task description, sequence, zone, staff, board, and phase. Task GUIDs are retained in metadata but should not be the primary operator-facing identifier.

Use this tab to:

  • Open a selected run.
  • Read the dashboard log.
  • Review artifacts, repository participation, critic reports, and eDoc upload state.
  • Fetch the evidence report when available.

MCPs Tab

Shows required MCP health and supports reauthentication tracking.

Status Meaning Operator action
ready The MCP is configured and usable. No action.
stale Credential or readiness state is too old to trust. Use reauth flow or restart the affected worker after credentials are refreshed.
unauthenticated Credential is missing or expired. Reauthenticate the service account/OAuth profile, then verify readiness.
unavailable MCP server cannot be reached or tool namespace is absent. Check MCP server registration, network, and local process logs.
degraded Service works partially but does not satisfy execution policy. Pause live work until the missing capability is restored or a human waiver is recorded.

Tooling Tab

The Tooling tab is split into runtime dependencies and skill/plugin catalogs.

  • Runtime dependencies: edi, ediprod, wtgkb, sbkb, agent runtime tooling.
  • Skill and plugin catalogs: project skills from skills-lock.json, WTG.AI.Prompts, and future marketplace/plugin catalog sources.
  • Update jobs: queued update operations for tools that have a supported automated update handler.

A missing WTG.AI.Prompts local clone does not prevent dry-run scouting. It means local prompt-repo update actions are unavailable and workers should use installed project skills plus wtgkb or GitHub metadata fallback for prompt guidance.

Learning Tab

Shows self-learning assessments created by dedicated PAVE learning tasks. These are separate from normal coding/review tasks. The expected PAVE shape is task type INT with Self Learning in the task description.

6. Daily Operations

Morning readiness check

  1. Start or verify services with .\scripts\factory-services.ps1 status.
  2. Open /factory.
  3. Confirm one live instance for the expected staff code and board.
  4. Confirm required MCPs are ready.
  5. Confirm Tooling shows no update-required items unless explicitly pinned/waived.
  6. Confirm active queue is empty before allowing the scout to start live PAVE work.

Dry-run monitoring

In dry-run mode the scout can discover startable tasks and write portal runs without mutating PAVE. This is the preferred mode for validating configuration, board visibility, MCP readiness, and task classification.

Dry-run runs should have:

  • Status dry run.
  • Phase scout dry run for normal delivery tasks.
  • Phase self learning dry run for dedicated learning tasks.
  • No PAVE claim/start side effect.

Live work enablement

Only enable live mode after all of these are true:

  1. The PAVE board and execution staff code are correct.
  2. The scout sees no currently playing task for the execution staff code.
  3. ediprod, wtgkb, and sbkb are ready.
  4. The operator has accepted the OAuth/staff-code policy.
  5. Archon workflow dispatch is configured and tested.
  6. Guardian assignment and suspend paths are verified.
$env:FACTORY_SCOUT_DRY_RUN = "false"
$env:FACTORY_ARCHON_EXECUTE = "true"
Live mode changes PAVE state. It may claim/start a task and can affect the playing-task state for the configured staff code.

7. Administrator Setup

Prerequisites

  • Windows PowerShell.
  • Python and Node runtimes as used by the repo.
  • uv for backend commands.
  • Node package manager available for frontend commands.
  • ODBC Driver 18 for SQL Server when using SQL Server storage.
  • Access to PAVE/ediProd through the edi CLI and MCP services.
  • Codex/agent MCP configuration containing ediprod, wtgkb, and sbkb.
  • Optional local vault/repo paths: C:\git\WTG.sbkb-mcp, C:\git\SecondBrain, and C:\git\WTG.AI.Prompts.

First setup sequence

  1. Clone the repo.
  2. Install backend and frontend dependencies according to existing project tooling.
  3. Create or select a SQL Server database, normally DarkFactory.
  4. Configure .env or PowerShell environment variables.
  5. Run edi login or equivalent OAuth setup.
  6. Verify edi staff get returns the expected OAuth staff code.
  7. Verify codex mcp list includes ediprod, wtgkb, and sbkb.
  8. Start services.
  9. Open the dashboard and confirm readiness.

SQL Server storage

Recommended local SQL Server connection for the current workstation:

FACTORY_STORAGE_PROVIDER=sqlserver
FACTORY_SQLSERVER_CONNECTION_STRING="Driver={ODBC Driver 18 for SQL Server};Server=RYZEN2;Database=DarkFactory;Trusted_Connection=yes;Encrypt=yes;TrustServerCertificate=yes;Application Name=Dark Factory;"

The application creates factory tables idempotently on first use. Use a shared SQL Server database for multi-instance coordination. SQLite is for local smoke testing only.

SQLite smoke-test storage

FACTORY_STORAGE_PROVIDER=sqlite
FACTORY_SQLITE_PATH=.factory/factory.sqlite3

Factory-only mode

FACTORY_API_ONLY=true runs only the PAVE factory API/worker surface and bypasses the inherited chat/RAG Postgres startup path. This is the normal local mode for this worker experiment.

9. PAVE Rules

Startable work discovery

  1. Required MCPs are checked first.
  2. The scout reads staff tasks and board channel fallback data.
  3. The scout filters to the configured board and execution staff code.
  4. The scout checks no task is already playing for the execution staff code.
  5. The scout selects one startable task, preferring earlier board zones and startable/release times.
  6. The scout resolves the selected row to a PAVE task ID and workflow ID.
  7. Dry-run mode records the selection; live mode continues to claim/start gates.

Single playing-task constraint

PAVE allows only one playing task per staff code. Starting a new task can suspend any currently playing task for that staff code. The worker therefore checks playing tasks before starting work and rechecks before live mutation.

Guardian escalation

When clarity or failures are detected after PAVE mutation, the worker should:

  1. Append a task note explaining the failure or clarity gap.
  2. Suspend the task when possible.
  3. Assign the item/task to the guardian staff code.
  4. Record the escalation in the dashboard log and evidence report.

Self-learning task shape

A dedicated PAVE self-learning task is recognized only when both conditions are true:

  • Task type is INT.
  • Task description contains Self Learning.

These tasks route to FACTORY_SELF_LEARNING_WORKFLOW_NAME and should not be treated as ordinary coding/design/review tasks.

10. MCP, Skills, and Tooling

Required MCP roles

MCP Role Fail-closed behavior
ediprod PAVE lifecycle, work item/incident updates, task notes, eDoc upload. Pause PAVE polling and live task mutation.
wtgkb Current WTG/CargoWise/PAVE knowledge retrieval for the task. Block or require human approval for high-risk coding tasks.
sbkb Durable Second Brain learning storage, mainly during dedicated self-learning tasks. Do not write durable learning notes; record degraded learning state.

Skills and plugin use

Skills and plugins are controlled inputs, not decoration. The DAG should nominate the allowed skills for each node. Claude-backed Archon nodes can pass these through native per-node skills:. Codex-backed nodes currently discover skills globally, so the executor must enforce the allow-list by loading only nominated skill context and recording what was used.

Installed skill catalog

The project skill catalog is tracked by skills-lock.json. Current locked project skills include PAVE, ediProd, ediProd CLI, Glow API, code review, work item status, and board troubleshooting guidance.

WTG.AI.Prompts

WTG.AI.Prompts should be treated as a marketplace/catalog source. Do not bulk-load the entire repository into every node. Select phase-specific and domain-specific skills/plugins, record the decision, and persist usage to run artifacts and skill invocation storage.

11. Archon and Repository Execution

Normal delivery workflow

Normal PAVE delivery tasks use pave-dark-factory-execute-task. The workflow should cover task contract loading, repository set discovery, context gathering, implementation, validation, critic review, reporting, and close/suspend handling.

Self-learning workflow

Dedicated self-learning tasks route to pave-dark-factory-self-learning. This workflow should compare generated artifacts with what was actually used, identify manual changes, create a learning assessment, and write approved durable learning to sbkb.

Modular CargoWise repositories

CargoWise work can span the main CargoWise repository and one or more sibling CargoWise.* repositories. A single PAVE work item may require multiple branches, PRs, build plans, test plans, and evidence records.

Repository-set evidence

Each run should record:

  • Repository name and path.
  • Base branch and worker branch.
  • Commit SHA and PR URL when created.
  • Build/test command and result.
  • Artifacts generated for that repository.
  • Any repository access, dirty state, or build blocker.

12. Evidence and eDoc

Every real run should produce an audit/evidence report against the PAVE job eDoc. The evidence report must include the same full log visible in the dashboard, plus critic output and links or references to generated artifacts.

Evidence report minimum contents

  • Run ID and instance ID.
  • PAVE job number, task ID, task code, task description, board, staff code, and guardian code.
  • Claim/start/suspend/complete attempts and results.
  • Full dashboard event log.
  • Repository participation and PRs.
  • Generated artifacts: specs, coding, review, validation, critic, final report, self-learning assessment.
  • Critic findings and verdict.
  • eDoc upload status and document ID.
  • Failures, retries, escalations, and guardian assignment.

eDoc file type

Internal evidence should use INT when accepted for the job type. The current worker evidence upload helper defaults to INT.

13. Self-Learning

Self-learning is not part of the coding task. It is a later PAVE task that assesses whether the generated artifact was used as generated.

Trigger

The task must match both of these conditions:

  • type == INT
  • description contains Self Learning

Workflow objective

  1. Load the original run artifacts and accepted final artifact.
  2. Compare generated output with manual or downstream changes.
  3. Create self-learning-assessment.json and self-learning-assessment.md.
  4. Surface learnings and confidence levels.
  5. Write approved durable learnings to sbkb.
  6. Record sbkb note IDs in the portal and PAVE.
The critic node may identify learning candidates, but it must not write durable Second Brain notes. Durable writes belong in the dedicated self-learning PAVE task.

14. Security and Controls

Worker token

Worker API routes require X-Factory-Worker-Token and X-Factory-Instance-Id. The local service script creates .factory/factory-worker-token.txt when needed. Treat this token as a local secret.

OAuth and staff-code mismatch

The local OAuth profile may be PWS while the execution staff code is C50. Live PAVE mutation is blocked unless FACTORY_ALLOW_OAUTH_STAFF_MISMATCH=true is explicitly set.

Least privilege

  • Do not grant workers broad PAVE mutation ability unless the play guard and guardian escalation are working.
  • Do not allow stale or unauthenticated MCPs to produce partially trusted results.
  • Do not allow skill/plugin updates to occur silently before execution. Updates should be visible and auditable.
  • Do not expose worker tokens, OAuth token files, SQL Server credentials, or logs containing sensitive job data.

16. Troubleshooting

Symptom Likely cause Action
Dashboard shows multiple old instances. Stale instance rows are being returned or service restart did not stop old worker processes. Restart with factory-services.ps1 restart. Verify API filters live instances only.
Active queue shows a dry-run item. Dry-run selection was saved as queued. Dry-run runs should have status dry_run and phase scout_dry_run or self_learning_dry_run.
Tooling rows repeat many times. Historical instance-specific tooling inventory is not filtered. Use the current repository filtering; Tooling should show only live/global rows.
edi staff tasks C50 returns zero but board has tasks. C50 may not have a published staff board view through that CLI path. Use board channel fallback. Verify FACTORY_PAVE_BOARD_CHANNEL_FALLBACK=true.
MCP is stale or unauthenticated. Credential expired, server missing, or tool registration changed. Reauthenticate, restart the affected process, and verify MCP readiness before live work.
Live start is blocked due to OAuth mismatch. OAuth staff code is PWS while execution staff code is C50. Either authenticate as C50 or explicitly set FACTORY_ALLOW_OAUTH_STAFF_MISMATCH=true after accepting the risk.
WTG.AI.Prompts shows unavailable. Local clone is missing at C:\git\WTG.AI.Prompts. Install/clone it if local updates are required, or rely on installed project skills plus wtgkb/GitHub metadata fallback.
Self-learning task routes to normal workflow. Task is not type INT, or description does not contain Self Learning. Correct the PAVE task type/description or adjust the classifier only after governance approval.
SQL Server connection fails. Wrong database, driver, encryption, or Windows authentication context. Verify ODBC Driver 18, database name, integrated security, Encrypt=yes, and TrustServerCertificate=yes for local dev.
